# 2026-10-11 코드 리뷰 범위와 결정

기준 소스는 `4d2f8130a63d9fed0009fbc4ae15e355b0c2832f`이다. Ponytail Audit의 위험 점검 방식을 중심으로 OpenCodeReview CLI 1.12.13의 파일별 규칙을 체크리스트로 활용하고, Graphify 질의의 관계를 실제 소스·테스트·규칙과 대조했다. OpenCodeReview의 별도 모델 API 리뷰를 실행한 것은 아니다.

전체 입력 335개는 목록·해시·정적 위험 패턴과 규칙 적용 여부를 점검했다. CLI 규칙은 303개 파일에 반환됐다. 자동 열람 기록으로 확인되는 집중 소스 검토는 76개이며 나머지 259개는 목록·정적 패턴 점검 수준이다. 모든 파일을 줄마다 읽거나 모든 실행 경로를 검증한 전수 리뷰로 표현하지 않는다. 회차·일정·공개 응답 서비스의 일부 쓰기 경로도 집중 검토 기록이 부족하다.

합성 데이터와 실제 소스를 사용하는 재현에서 조건부 위험 7건을 제시했다. 7건이라는 수는 발견·재현한 결과이며 전체 결함의 개수나 결함 부재를 보증하지 않는다. 이후 요구사항 논의에 따른 결정은 다음과 같다.

| 항목 | 결정 |
| --- | --- |
| 지원자 전환 중 대기 메모 저장이 다른 지원자 입력을 읽는 문제 | 수정. 화면을 닫기 전에 저장을 확인하고 실패하면 입력·화면을 유지한다. 이전 지원자의 대기 작업과 구독 응답을 분리한다. |
| 세션 전체 저장에 따른 동시 수정 손실 | 알려진 문제이며 사용자가 수정하지 말도록 지정했다. |
| 세션 조 병합에 따른 다른 필드 수정 손실 | 알려진 문제이며 사용자가 수정하지 말도록 지정했다. |
| 오래 열린 수동 면접 배정 화면에서 완료 상태를 되돌릴 가능성 | 알려진 문제이며 사용자가 수정하지 말도록 지정했다. |
| 관리자 이메일 중복 추가에 따른 마스터 권한 변경 | 수정. 서버 트랜잭션에서 중복을 거절하고 기존 권한·생성 시각을 보존한다. |

메모 저장 지연·실패·지원자 전환·늦은 구독 응답·닫기 재시도와 관리자 중복·동시 추가를 회귀 테스트로 확인했다. 운영 자료를 재현이나 시험 데이터로 사용하지 않았다. 배포 결과와 검증은 [운영 가이드](operations.md)에 기록한다.
