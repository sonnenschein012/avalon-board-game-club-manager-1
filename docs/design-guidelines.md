# Avalon 목표 디자인 기준

작성일: 2026-09-14. 디자인 피드백 후 사용자가 진행을 요청하여 작성한 **후속 시안과 구현을 위한 기준안**이다. 아래 수치는 제안값이며 실제 화면 검증을 완료했다는 뜻이 아니다. 현재 구현의 관찰 기록은 [DESIGN.md](../.stitch/DESIGN.md)에 그대로 보존한다. 앱에 아직 적용하지 않은 목표값을 현재 구현값으로 인용하지 않는다.

## 1. 방향과 사용 맥락

**차분한 네이비를 기반으로, 사람과 진행 상태가 먼저 읽히는 동아리 운영 도구.**

공간은 이름 식별, 현재 상태 이해, 다음 행동에 먼저 배분한다. 색·굵기·그림자를 동시에 올려 중요도를 표현하지 않는다. 화면의 실제 업무 단위마다 주요 행동을 하나씩 정하고, 부가 작업은 보조 행동으로 배치한다.

| 맥락 | 사용자가 알아야 할 것 | 디자인 기준 |
| --- | --- | --- |
| 관리자 명부·기록 | 찾는 사람/게임, 현재 필터, 수정 대상 | 검색과 목록의 연결, 읽기 쉬운 이름, 행별 조작의 일관성 |
| 현장 출석·편성·진행 | 배정/미배정 인원, 조 구성, 다음 단계 | 인원과 이름 우선, 명확한 실행 문구, 긴 목록 사이 이동 지원 |
| 공개 면접 응답 | 선택 방법, 선택한 시간, 저장 여부, 수정 가능 여부 | 설명과 입력을 가까이 배치, 모바일 조작, 저장 결과 유지 |
| 모임 현장 캔버스 | 조 이름, 참가자, 진행 정보 | 검은 배경 유지 가능, 실제 표시 크기의 가독성 우선 |

관리자·공개 화면·현장 캔버스는 같은 글자·행동·상태 원칙을 공유하되 배경과 밀도는 맥락에 맞게 다르게 한다. 로고의 Navy/Gold는 그대로 보존한다.

## 2. 글자와 정보 밀도

아래 크기는 CSS px 기준 시작값이다. 실제 한글 글꼴과 390/768/1440px 화면에서 확인한 후 조정한다.

| 역할 | 크기 / 행간 | 굵기 | 사용 조건 |
| --- | --- | --- | --- |
| 페이지 제목 | 모바일 22/30, 데스크톱 24/32 | 700 | 화면당 대표 제목 |
| 섹션 제목 | 18/26 | 700 | 업무 영역 구분 |
| 회원·참석자 이름, 주요 본문 | 14/22 | 400~600 | 이름은 600, 설명은 400 |
| 공개 입력과 주요 설명 | 16/24 | 400~600 | 휴대전화 응답 기준 |
| 버튼·폼 라벨 | 14/20 | 600 | 라벨은 입력 밖에 항상 표시 |
| 보조 정보·메뉴 라벨 | 12/18 | 400~600 | 필수 이름·상태를 이 크기로 축소하지 않음 |
| 현장 표시용 캔버스 | 별도 실측 | 600~700 | 원본 1600px 내부 수치보다 축소 후 읽히는 크기로 판단 |

- 9~11px는 새 화면의 업무 정보에 사용하지 않는다. 목록이 길면 바깥 여백, 열 구성, 부가 정보 노출량부터 조정한다.
- 800·900 굵기는 기본 UI에서 제외한다. 영문 부제는 장식적 보조 정보로 취급하고, 사용법이나 상태 설명을 대신하지 않는다.
- 한국어 본문은 기본 자간을 사용한다. uppercase와 넓은 자간을 한글 라벨의 공통 규칙으로 적용하지 않는다.
- 첫 시안은 시스템 한글 글꼴로 제작하고 Windows와 모바일에서 실제 적용 글꼴을 기록한다. 별도 웹폰트 도입은 실측 후 판단한다.
- 긴 이름·게임명은 줄바꿈이나 상세 보기로 전체 내용을 확인할 수 있어야 한다. 모바일에서는 hover 툴팁만으로 전체 정보를 제공하지 않는다.

## 3. 색상과 표면

다음 이름은 목표 역할이며 현재 코드의 토큰 이름이 아니다. 아래 hex를 Tailwind 4의 동명 Slate 클래스와 동일한 값으로 간주하지 않는다.

| 역할 | 제안값 | 사용 |
| --- | --- | --- |
| 작업 바탕 | `#F8FAFC` | 관리자 바깥 영역, 공개 화면 바탕 |
| 표면 | `#FFFFFF` | 목록·입력 영역·모달 |
| 주요 글자 / 주요 행동 | `#0D1B2A` | 제목, 본문, 기본 주요 버튼 |
| 보조 글자 | `#64748B` | 부가 설명, 시간·학번 등 |
| 주요 행동 hover | `#243649` | 흰 글자 유지 |
| 장식 경계 | `#E2E8F0` | 패널·행 구분, 입력 식별의 유일한 수단으로 사용하지 않음 |
| 입력 경계 | `#64748B` | 흰 입력 표면의 외곽선 |
| 브랜드 강조 | `#C5A059` | 작은 강조, 드롭 위치 보조 표시; 위 글자는 Navy |
| 시간 선택 | `#FFD166` | 기존 시간 격자 강조 유지, 체크 표시 병행 |
| 위험 행동 | `#8E1616` | 삭제 등 되돌리기 어려운 실행 |

정적 sRGB 계산에서 Gold/White는 약 2.46:1, Navy/Gold는 7.08:1이다. 따라서 주요 버튼은 호버 때 Navy에서 다른 어두운 Navy로 바꾸고 흰 글자를 유지한다. 보조 글자/White는 4.76:1, 보조 글자/작업 바탕은 4.55:1이다. 이는 불투명 단색의 계산이며 실제 렌더링·반투명·모든 상태의 검증 결과가 아니다.

프로젝트 검증 목표는 업무 텍스트 대비 4.5:1 이상, 조작 식별과 포커스 표시 대비 3:1 이상으로 잡는다. 기본 상태뿐 아니라 호버·선택·오류 상태도 측정한다. 비활성 상태에서도 사용할 수 없는 이유를 읽을 수 있게 한다.

상태는 반드시 문구와 함께 표현한다. 조별 색상과 차트 계열색은 별도로 유지하고 범례·조 이름을 함께 표시한다. 사용자 지정 카드 색상은 밝기에 맞춰 글자색을 선택하거나, 검증된 불투명 텍스트 바탕을 제공한다.

## 4. 공통 컴포넌트

### 버튼

| 역할 | 형태 | 예 |
| --- | --- | --- |
| 주요 | Navy 채움 / 흰 글자, 기본 그림자 없음 | 회원 저장, 편성 실행, 응답 저장 |
| 보조 | 흰 표면 / 경계 / Navy 글자 | CSV 가져오기, 취소, 조건 설정 |
| 부가 | 투명 표면 / 글자와 아이콘 | 상세 보기, 목록 펼치기 |
| 위험 | 확인 단계에서 Crimson 채움 / 흰 글자 | 삭제 확인 |

- 기본 모서리 10px, 데스크톱 높이 40px, 터치 조작은 최소 44×44px 영역을 확보한다. 아이콘 자체 크기와 조작 영역 크기를 구분한다.
- 같은 작업 영역에서 주요 버튼이 경쟁하면 다음 필수 행동을 주요로, 다시 실행·설정·내보내기를 보조로 표현한다. 이를 이유로 유효한 기존 작업을 숨기거나 막지 않는다.
- hover는 색 변화, pressed는 더 짙은 표면으로 표현한다. 상시 pulse는 사용하지 않고 처리 중 회전 표시는 모션 감소 설정을 존중한다.
- `focus-visible`은 Navy 2px 외곽선과 2px 간격을 기본으로 한다. 어두운 바탕에서는 밝은 분리선을 추가하여 구분한다.
- 처리 중에는 `저장 중…`처럼 실행 내용을 유지하고 중복 실행을 막는다. 비활성 조건은 가까운 설명으로 알린다. 오류 후 입력과 재시도 경로를 유지한다.
- 아이콘 버튼은 `홍길동 수정`처럼 대상과 행동을 접근성 이름으로 제공한다. 툴팁은 보조 수단이다.

### 입력·검색·선택

- 같은 역할의 입력은 흰 바탕, 공통 경계, 10px 모서리, 14px 글자를 사용한다. 공개 응답 입력은 16px를 사용한다.
- placeholder를 라벨 대신 쓰지 않는다. 오류는 해당 입력 아래에 이유와 수정 방법을 제공하고 입력과 프로그램적으로 연결한다.
- 기본/hover/focus/입력 오류/비활성/읽기 전용 상태를 각각 정의한다. 읽기 전용과 비활성의 이유가 혼동되지 않게 한다.
- 검색 결과 없음과 데이터 없음, 조회 실패를 구분한다. 검색 결과 없음에는 필터 해제, 조회 실패에는 다시 시도를 제공한다.

### 카드·모달·여백

- 패널 모서리 16px, 입력·버튼 10px, 상태 배지 pill을 기본으로 한다. 공개 면접 헤더의 24px는 유지할 수 있다.
- 페이지 바깥 여백은 모바일 16px, 태블릿 24px, 데스크톱 32px로 시작한다. 패널 안은 16~24px, 섹션 간격은 24px로 한다.
- 4px 간격 단위를 기본으로 사용하되 8px 배수만을 강제하지 않는다. 화면 폭을 확보하려고 핵심 글자를 줄이지 않는다.
- 기본 카드에는 얕은 경계만 사용하고, 그림자는 떠 있는 메뉴·모달·드래그 미리보기에 집중한다. 제목 영역은 필요 없는 카드 중첩을 줄인다.
- 목록과 시간표는 가용 폭을 사용한다. 긴 설명·폼은 읽기 편한 폭으로 제한하며 모든 페이지에 동일 max-width를 강제하지 않는다.
- 모달은 열릴 때 포커스를 내부로 이동하고 닫힐 때 실행 버튼으로 돌려준다. 작은 화면과 가상 키보드에서도 내용·실행 버튼에 접근할 수 있어야 한다.

## 5. 업무 상태와 문구

| 상태 | 화면이 알려야 할 것 | 행동 기준 |
| --- | --- | --- |
| 조회 중 | 데이터를 불러오는 중 | 기존 오류·빈 상태와 구분 |
| 조회 실패 | 불러오지 못한 대상 | 지속되는 안내와 다시 시도, 빈 데이터로 오해시키지 않음 |
| 편성 중 | 현재 배정·미배정 인원 | 편성 조건과 실행, 조정, 모임 시작의 결과를 구분 |
| 모임 시작 저장 중 | 현재 편성을 기록하는 중 | 중복 실행 방지, 성공 전 확정 표시 금지 |
| 저장 완료 | 무엇이 저장됐는지 | 문구로 결과 확인, 수정 가능 범위 안내 |
| 저장 실패 | 변경이 저장되지 않았음 | 입력 유지, 재시도; 성공 안내 표시 금지 |
| 면접 미응답 | 아직 저장한 응답이 없음 | 응답 입력 안내 |
| 가능한 시간 없음 | 빈 선택을 명시적으로 저장함 | 미응답과 구분, 기존 빈 선택 확인 절차 유지 |
| 선발 결과 | 보류/합격/불합격 등 실제 상태 | 색과 텍스트 병행, 배정·응답 상태와 별도 표현 |

자동 편성의 버튼 문구는 `자동 편성 실행`, 세션 기록 생성은 `모임 시작`을 후보로 삼는다. 모바일에서도 두 버튼을 모두 `시작`으로 줄이지 않는다. 실제 실행 의미는 연결된 hook/service로 검증하고 문구 때문에 정책을 바꾸지 않는다.

계획과 확정 기록은 별도 데이터라는 [개발 가이드](development.md)의 구분을 유지한다. 참석자 ID와 회원 ID, absent/empty boardMemberIds, 기존 면접 scheduleId 의미는 시각 개편으로 변경하지 않는다. 이미 구현된 공개 응답 저장 확인·완료 안내와 조회 오류·재시도도 유지한다.

## 6. 모바일과 업무 전용 UI

2026-09-14 사용자 답변: 관리자용 모바일에서 특별히 우선할 업무는 없음. 특정 업무 중심의 메뉴 재구성은 추진하지 않고 기존 탐색 구조를 유지한다. 모바일은 기존 업무를 잘림·가림 없이 읽고 조작할 수 있는 것을 공통 기준으로 삼는다. 이는 모바일 지원을 제외한다는 뜻이 아니다.

- 기존 하단 메뉴의 활성 항목 자동 스크롤과 양끝 이동 힌트를 보존한다. 12px 라벨로 긴 메뉴를 확인할 수 있는지 검증한다. 고정 메뉴와 안전 영역이 마지막 목록·버튼을 가리지 않게 한다.
- 조 편성은 미배정 인원 요약과 미배정/조 영역 사이 이동 수단을 시안으로 검토한다. 기존 키보드 드래그를 유지하고, 터치에서 사용할 `조 이동` 대상 선택 방식은 기존 이동 서비스와 같은 결과를 내도록 설계한다.
- 공개 시간표는 최소 44px 높이의 조작 칸을 사용한다. compact 32px 표현은 데스크톱 밀집 보기로 한정하는 방향을 검토한다. 시간·날짜 고정 제목을 유지한다.
- 시간 선택에 색상과 체크 표시를 병행한다. 기존 aria-pressed, 날짜·시간 접근성 이름, 키보드 활성화와 연속 선택을 보존한다.
- 시간표 스크롤과 손가락 연속 선택이 충돌하지 않는지 확인하고 격자 밖 스크롤 경로를 확보한다. 마지막 날짜까지 이동하고 선택 취소·저장까지 완료할 수 있어야 한다.
- 현장 캔버스는 일반 관리 화면과 별도로 검증한다. 축소 화면에서 식별이 어려우면 더 작은 글자 대신 조별 보기나 확대 진입을 검토한다. 고정 1600px 설계를 즉시 제거하지 않는다.

## 7. 적용 순서와 완료 기준

[제품 완성 계획](product-completion.md)의 기존 작업 순서를 대체하지 않는다. 해당 작업을 진행할 때 이 문서의 표현 기준을 적용하며, 전체 UI를 한 번에 교체하지 않는다.

1. 회원 목록 하나를 기준 화면으로 시안화한다. 이름·버튼·검색·필터·빈 상태·오류를 함께 비교하여 공통 기준을 확인한다.
2. 확인한 글자·버튼·입력 스타일을 공통화하고 다른 화면은 업무 단위로 적용한다. 기존 컴포넌트 호출부와 반응형 배치를 함께 확인한다.
3. 공개 면접은 시간 선택과 저장의 상태 연속성을, 현장 편성은 이름 식별과 배정 이동을 검증한다.
4. 완료된 화면마다 변경 전후 합성 데이터 화면과 검증 결과를 남긴다. 승인된 목표 변경은 이 문서에, 구현 관찰 갱신은 별도 추출 절차에 기록한다.

| 검증 화면/조건 | 완료 기준 |
| --- | --- |
| 회원 목록: 기본·과밀·긴 이름·검색 결과 없음 | 이름과 대상별 수정 조작을 읽고 찾을 수 있음, 숨긴 전체 정보에 접근 가능 |
| 공통 폼: 키보드·오류·저장 중·실패 | 현재 포커스가 보임, 입력 유지, 중복 실행 없음, 결과 상태 구분 |
| 조 편성: 과밀·미배정·조 이동 | 이동 후 인원 일치, 키보드/터치 작업 완료, 계획 데이터 보존 |
| 공개 면접: 미응답·빈 응답·기존 응답 수정·마감 | 서로 다른 상태를 구분, 선택/해제/저장/결과 확인 가능 |
| 390/768/1440px, 텍스트 확대 200% | 주요 글자·버튼 잘림 없음, 고정 UI의 가림 없음; 시간표의 의도적 내부 스크롤은 허용 |
| 현장 캔버스: 일반·전체 화면·사용자 지정 색 | 실제 표시 크기로 이름 식별, 텍스트 대비 유지 |

시각·반응형 검증은 Scenario Lab의 합성 데이터로 한다. 저장·드래그·권한 흐름 변경은 Emulator Design Lab에서 실제 hook/service 경로도 확인한다. 필요한 상태가 fixture에 없으면 검증용 상태를 보완한다. 운영 데이터를 테스트에 쓰지 않는다. 검증 명령과 배포 절차는 [개발 가이드](development.md)와 [운영 가이드](operations.md)를 따른다.

## 8. Stitch에 전달할 범위

현재 화면 재현에는 `.stitch/DESIGN.md`를 사용한다. 개선 시안에는 이 목표 문서를 우선 전달하고 현재 추출본은 변경 전 참고라고 명시한다. 동일 값으로 충돌할 경우 재현/개선 목적부터 구분한다.

개선 시안 예시:

> 한국어 동아리 관리자용 회원 목록 개선 시안을 만든다. 차분한 Navy, 연한 작업 바탕과 흰 표면을 사용한다. 회원 이름과 주요 조작은 14px 이상, 보조 정보는 12px 이상으로 한다. 회원 추가를 주요 행동으로, CSV 작업을 보조 행동으로 배치한다. 검색·필터·목록 순서를 유지하고 기본·과밀·검색 결과 없음·조회 실패 상태를 포함한다. 390/768/1440px에서 글자를 축소하지 않고 배치를 조정한다. 개인정보는 합성 데이터를 사용한다. 데이터 필드·업무 정책·메뉴 구조는 임의 변경하지 않는다.

이 문서 작성 시 Stitch 전송, UI 구현, 브라우저 시안 검증과 배포는 수행하지 않았다.
