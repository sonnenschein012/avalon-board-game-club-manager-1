# 독립 세션 기록과 통계

모임을 시작할 때마다 새 Firestore 자동 ID를 트랜잭션 밖에서 한 번 발급한다. 날짜의 DailyPlanning을 먼저 읽고 같은 날짜의 저장된 세션 이름을 조회한다. 이름이 있으면 (2)부터 사용하지 않은 접미사를 선택한다. 같은 날짜의 동시 시작은 DailyPlanning 충돌로 재시도하며 이름을 다시 조회한다. 수동 기록 생성/이름 수정은 이 잠금에 참여하지 않으므로 이들과 동시에 수행하는 이름 변경까지 유일성을 보장하지 않는다. 시스템 식별은 항상 ID다.

모든 세션은 독립 기록이다. 동일 날짜 또는 모임 재시작을 이유로 이전 세션을 수정하거나 제외하지 않는다. 대체 세션 개념과 supersededBy 처리는 사용하지 않는다. DailyPlanning은 별도 운영 문서이며 시작 시 새 세션 ID로 연결한다. 이전 계획 버전 보존 기능은 그대로 유지한다. 기존 세션의 ID/편성/게임 기록은 유지한다. 데이터 마이그레이션은 필요하지 않다.

## 집계 기준

통계의 참석·플레이 이력은 세션 기록 탭과 같은 sessions 컬렉션만 사용한다. 회원과 게임은 이름/가입 학기 등의 부가 정보에 사용한다. DailyPlanning이나 그 버전은 통계에 추가하지 않는다.

- 참여 순위와 회원 CSV의 누적 참여 횟수는 세션별 참여 횟수다. 한 세션 안에서 중복 회원은 한 번만 세며 같은 날짜의 별도 세션은 각각 센다. 순위 참석률의 분모는 기존처럼 세션 수다.
- 출석·신입·정체 시계열은 날짜별로 모든 세션의 회원 ID 합집합을 사용한다. 기존 날짜 해석과 같은 로컬 달력 날짜로 묶고 날짜순으로 정렬한다. 정체 지수의 누적 횟수/분모도 출석일 수/개최일 수로 맞춘다. 신입 시계열의 최소 3명 조건은 날짜별 합집합에 적용한다.
- 인기 게임, 코어 플레이어, MMI, 추천은 모든 독립 세션의 기록을 사용하며 날짜 중복만으로 제외하지 않는다.

화면 안내: ※ 동일 날짜에 여러 세션이 있는 경우, 해당 날짜의 모든 세션 기록을 바탕으로 출석자를 중복 없이 집계합니다.

## CSV

기존 파일명과 기본 표시 열을 유지하며 세션 ID, 조 데이터 JSON, 임원 ID 목록을 추가한다. 조 ID/회원 ID/게임 ID/메모/게스트와 빈 세션을 보존한다. ID 없는 CSV는 날짜+이름으로 묶고 ID 있는 CSV는 ID로 묶는다. 같은 ID의 이름/날짜 불일치는 거부한다. 가져오기는 최대 400개를 한 트랜잭션으로 수행하며 기존 ID가 하나라도 있으면 전체 취소하여 덮어쓰지 않는다. 빈 대상에서는 세션의 ID/이름/날짜/조 구성을 복원한다. createdAt 등 모든 Firestore 메타데이터를 복원하는 DB 덤프는 아니다.

## 검증과 남은 경계

실제 Firestore Emulator에서 동시 시작을 검증하는 통합 테스트는 별도 필요하다. 수동 생성/수정까지 이름 예약을 통합하는 작업은 현재 범위에 포함하지 않았다. 세션 목록 UI는 기존 날짜 내림차순을 유지한다. 운영 데이터 변경과 배포는 수행하지 않았다.
