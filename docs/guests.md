# 게스트 참석과 익명 세션 기록

게스트는 `members`에 만들지 않습니다. `Attendee.participantType: 'guest'`로만 구분하며 `memberId: null`, 고유 참석자 ID, 이름, 음료, `invitedByAttendeeId`를 저장합니다. 초대 참조는 회원 참석자의 ID입니다. 정식 회원의 `participantType` 부재와 `memberId` 부재(legacy 조회), `null`(명시적 미등록)의 의미는 유지합니다.

수동 추가에서는 참석 중인 등록 회원을 선택하고 이름과 선택 음료만 입력합니다. 게스트 이름은 필수이며 희망 음료는 수동 추가·CSV 모두 선택 사항입니다. 한 회원당 한 게스트이며 CSV 중복 회원 행도 거절합니다. 게스트 문서 ID는 초대자 참석자 ID에서 결정하고 수동 추가 트랜잭션에서 중복을 확인합니다. 게스트 추가는 회원 생성·휴면 복원을 실행하지 않습니다. 초대자 삭제·결석·회원 연결 소실은 경고하며 관계를 자동 삭제하지 않습니다.

자동 편성은 게스트를 정원에 포함하고 구조화된 초대 관계를 기존 동반 요청 쌍으로 평가합니다. 수동 배치와 기존 요청 우선순위는 유지합니다. 게스트는 성별·학번이 null이고 회원 이력이 없으며 회원 개인 효용 보호 평균에는 포함하지 않습니다. 회원과 게스트는 독립적으로 이동합니다. 분리되거나 상대가 미배정이면 기존 동반 요청 경고를 표시하되 저장은 허용합니다.

## 두 저장 경계

- `DailyPlannings.groups.memberIds`는 기존 회원 ID와 명시적 게스트의 참석자 ID를 담습니다. 참석자 snapshot에서 게스트 이름·음료·초대 참조를 보존합니다. 버전 복원도 같은 snapshot을 사용합니다. 당일 기록은 익명 세션 기록과 다릅니다.
- `sessions.groups.memberIds`에는 정식 회원 ID만 담고 게스트는 `guestCount?: number`로 변환합니다. 부재는 0이며 정규화는 0 이상의 안전한 정수만 허용합니다. 게스트 이름·참석자 ID·초대 참조를 세션에 복사하지 않습니다.

기존 모임 시작 동작처럼 연결된 확정 세션이 이미 있으면 세션의 회원·게임·게스트 수를 덮어쓰지 않습니다. 재시작은 운영 계획과 snapshot을 새로 저장하고 이전 계획을 버전으로 보존합니다. 확정 세션을 변경하려면 세션 기록에서 수정합니다. 이 구분은 당일 계획과 기록의 별도 편집을 보존합니다.

수동 세션 폼의 게스트 공급 카드는 회원 명부와 독립적인 UI 항목입니다. 항상 남아 있고 각 조에 반복 추가할 수 있습니다. 조 안의 카드는 `guestCount`에서 복원하며 조/인덱스별 드래그 ID로 충돌을 피합니다. 숫자 입력은 없습니다. 개별 제거와 조 사이 이동을 지원합니다. 정규화·기존 조 단위 병합·게임만 수정하는 경로에서 개수를 보존하며 감사 요약에는 실제 인원과 게스트 수를 표시합니다. 동일 조의 동시 편집은 기존 조 단위 병합 규칙을 따릅니다.

## CSV와 통계

세션 CSV 열은 그대로 유지하고 조원 명단에 정확히 `게스트` 토큰을 인원수만큼 반복합니다. 가져오기에서도 정확한 토큰만 인원으로 셉니다. 다른 미확인 이름을 게스트로 바꾸지 않습니다. 회원 닉네임·임원 snapshot·게임명 legacy 조회를 유지합니다. 게스트 없는 기존 CSV의 결과 형태도 유지합니다.

출석 CSV에는 선택 열 `게스트 동반 여부`, `게스트 이름`, `게스트 희망 음료`를 연결할 수 있습니다. 기존 열이 없는 양식은 그대로 동작합니다. 미리보기에서 게스트 정보를 수정하고 회원을 확정합니다. 초대자가 미등록이거나 이름 누락, 동반 여부 모순, 중복 회원이 있으면 전체 반영을 거절합니다. 반영은 기존 명단 교체와 함께 단일 batch로 처리합니다.

회원 명부 CSV와 기존 아카이브 지표는 회원 ID만 사용합니다. 게스트 수를 참석률·랭킹·신입·고착화·인기 게임·핵심 플레이어·MMI 계산에 넣지 않습니다. 당일 인원·음료·게임 인원 추천은 게스트를 포함하지만 학번·과거 출석 평균과 회원 게임 경험은 회원 자료만 사용합니다.

## 배포 전 확인

관련 단위/UI 테스트 외에 Emulator에서 게스트 등록·드래그·모임 저장·snapshot·세션 익명화·음료 표시를 확인합니다. staging 빌드와 번들 분리 검사를 마친 뒤 Hosting을 배포합니다. Rules/인덱스 변경은 없습니다. Firebase 배포 인증과 실제 운영 계정의 화면 확인은 별도로 필요합니다. 작업 중 공유 Graphify 묶음은 보존하고, 그래프 최신성 검증과 앱 테스트 결과를 구분합니다.

모임 진행 대시보드와 공지 이미지에서는 게스트도 이름만 표시합니다. 초대 관계 표식은 조편성 화면에서 유지하며 세션 기록 목록에는 익명 `게스트` 태그를 인원수만큼 개별 표시하며 부원 태그와 같은 디자인을 사용합니다. 세션 편집 화면의 게스트 카드·제거 버튼·추가 버튼도 부원과 같은 스타일을 사용합니다.
