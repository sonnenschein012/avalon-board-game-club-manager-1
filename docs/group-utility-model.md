# 개인 효용 모델

2026-10-09 기준. `src/domain/matching/personalUtility.ts`와 `autoAssignAlgorithm.ts`를 실제 앱의 편성·개인 점수 창·시뮬레이션 내보내기에 연결했다. `scripts/group-utility-prototype.mjs`는 독립적인 검토 평가기로 남긴다. 요청 완화·재회 감쇠·환산 보호 조정과 모의 검증을 수행했다. 보호 이후 완화의 새 구현은 아직 배포하지 않았다. 통계 수식·저장 문서·운영 데이터는 변경하지 않았다. 조 인원 결정은 [조 인원 구성 모델](group-sizing-model.md)을 먼저 적용하며 배포 상태는 [운영 이력](operations.md)에 기록한다.

## 평가 순서

확정된 조 인원을 채우고, 수동 배치한 사람을 유지하며, 모든 참석자를 정확히 한 번 배치한 후보만 평가한다. 현재 검증용 코드는 잘못된 후보를 입력 오류로 거부한다.

1. 명시적인 동반 요청 점수 `R` 최대화
2. 운영진 없는 조 수 최소화. 같은 수라면 4명 아닌 조의 운영진 공백을 최소화
3. 완화 전 개인 순효용에 최대 2배 보호를 정하고, 이후 요청 완화를 적용한 전체 점수 `W` 최대화

동반 요청이 정원을 넘거나 수동 배치와 충돌해도 조 인원을 다시 정하지 않는다. 요청을 덜 충족한 배치는 운영진 분산이나 추론적 점수가 좋아져도 앞설 수 없다. 상위 기준이 같은 경우에만 다음 기준을 비교한다. 모든 점수가 같으면 재현 가능한 탐색 순서에서 먼저 선택된 배치를 유지한다. 독립 검토 평가기의 완전 열거에서는 ID 순서로 동점을 처리한다.

## 요청사항 인식 정책 (2026-10-09 보완)

전체 이름과 성 없는 이름 모두 부분 문자열로 찾는다. 이름 앞뒤의 띄어쓰기·조사·호칭 제한과 허용 표현 목록은 사용하지 않는다. `민결이와같이하고싶어요`처럼 붙여 쓴 문장에서도 이름을 찾으며, 다른 단어 안의 동일한 글자도 후보로 잡힐 수 있다는 한계를 수용한다. 원문은 바꾸지 않는다.

- `companionRequests.ts`가 요청 상대를 한 번 해석해 편성·개인 평가·자동/수동 알림에서 함께 사용한다. 전체 이름의 포함 검사를 유지하고, 세 글자 한글 이름은 성을 뺀 두 글자도 인식한다. 성을 포함한 이름이 발견된 부분을 다시 짧은 이름으로 해석하지 않으며, 그 밖에 별도로 등장한 짧은 이름은 문장 위치나 뒤따르는 표현과 관계없이 찾는다. 그 밖의 이름은 전체 이름으로 확인한다.
- 상대 후보는 그날 참석 명단에서 본인·결석자를 제외해 찾으며 미배정도 포함한다. 회원 명부에만 있는 동명이인은 참석 후보 수를 늘리지 않는다. 여러 후보가 남으면 모두를 요청 상대로 연결하지 않고 해당 언급만 보류하며, 같은 원문의 다른 확정 요청은 유지한다. 미등록 참석 후보도 임의로 제외해 단일 상대를 만들지 않으며 등록 전에는 선택할 수 없다.
- 보류 알림 전체를 누르면 기존 모달 스타일의 `CompanionRequestModal`에서 원문·후보 이름·학번·닉네임을 확인하고 한 사람 또는 미확정을 선택한다. `선택 반영`으로만 확정하며 취소/Esc는 기존 선택을 유지한다. 선택 후에도 알림을 눌러 변경할 수 있다. 요청자가 미배정이면 화면 상단, 배정되면 해당 조에 한 번 표시한다.
- 상대 선택 모달은 흰 표면과 옅은 경계를 유지하고, 요청·후보 목록 사이 여백과 후보 행의 간격으로 구역을 구분한다. 긴 원문은 펼쳐 볼 수 있으며 작은 화면에서는 본문만 스크롤하고 하단 실행 버튼은 고정한다.
- 선택은 로그인 계정에 구분된 현재 브라우저의 편성 임시 저장에만 보관한다. 원문·후보의 출석/회원 ID·이름·학번·날짜가 바뀌면 이전 선택을 적용하지 않는다. 후보가 한 명으로 줄어도 이전 선택을 다른 사람으로 자동 전환하지 않는다. 날짜 변경·성공한 명단 교체/초기화·모임 시작 후 임시 저장 초기화는 선택도 비운다. 다른 운영진/브라우저에 공유하거나 Firestore 문서·Rules를 변경하지 않는다.
- 문장 의미·부정 표현의 자동 판별과 AI 해석은 추가하지 않는다. 전체 이름의 부분 문자열 검사와 부정 표현 해석의 기존 한계는 유지한다. 이 보완은 상대 식별을 위한 것이며 동반 요청의 점수·우선순위·관계식을 바꾸지 않는다.
- 이름이 매칭되지 않은 원문을 동반 요청이라고 단정하거나 동반 요청 미충족으로 경고하지 않는다.
- 상대가 이름으로 확인됐지만 해당 모임에 불참한 경우에는 요청 평가에서 제외하고, 불참으로 반영하지 못했다는 안내를 표시한다. 이 안내는 요청자가 속한 조에 표시한다. 아직 미배정된 요청자의 불참 상대 안내는 화면 상단에 표시한다.

## 확정한 함수 형태

### 동반 요청

`n_i`는 개인 i와 실제로 같은 조에 있는 **직접 요청 관계의 상대 수**다. 한쪽만 요청해도 양쪽에게 적용하고, 양방향/반복 요청은 같은 쌍으로 한 번만 센다. A–B–C 요청에서 A–C를 자동으로 새 요청 관계로 만들지 않는다.

`R = Σ_i ln(1 + n_i)`

처음 상대가 생기는 효과가 가장 크고, 추가 효과는 양수이면서 체감한다. A에게 네 사람이 요청하고 모두 함께 있으면 `ln(5) + 4 ln(2)`다. 요청 상대가 나뉘어 있으면 그 쌍은 충족 수나 완화 효과에 포함하지 않는다.

구현은 `P = ∏_i(1+n_i)`를 BigInt로 비교한다. `R = ln(P)`이므로 선호 순서는 같지만 소수점 합산 오차 때문에 동률을 잘못 판단하지 않는다. 화면 검토용으로 로그 점수도 함께 반환한다.

### 성별과 학번

동성 수 `s_i`, 이성 수 `o_i`는 본인을 제외한다.

- 동성 효용: `U_s = A_s(1 - exp(-k_s s_i))`
- 이성 효용: `U_o = A_o(1 - exp(-k_o o_i))`
- 조건: `k_s > k_o > 0`, `A_s(1-exp(-k_s)) > A_o(1-exp(-k_o))`

두 효용을 더한다. 동성 쪽이 더 빨리 포화되고 첫 동성 한 명의 효용이 더 크지만, 효용 상한의 대소는 별도로 결정한다.

상대 j와의 학번 차이는 선후배 방향을 구분하지 않는 절댓값 `d_ij`다.

- 상대별 비용: `c_ij = B(1 - exp(-h d_ij))`
- 조 전체의 개인 학번 비용: `C_year,i = -t ln[(1/m) Σ_j exp(-c_ij/t)]`

`m`은 본인 외 조원 수다. 가까운 사람이 있으면 부담이 줄고, 가까운 사람이 추가될 때의 완화는 체감한다. 먼 사람도 계속 평가에 포함된다. 전원이 같은 차이면 그 상대별 비용과 같아진다. 구현은 최소 비용을 빼고 지수를 계산하는 동치식으로 수치 안정성을 확보한다.

### 동반 상대의 완화와 재회

`w_i = exp(-k_request n_i)`

동반 상대가 많으면 성별·학번 구성의 영향이 줄어든다. 추가 상대의 완화 효과는 체감한다. 보호 판단을 먼저 수행하고 그 평가 기여분에 적용한다. 이 계수는 명시적 요청 점수에 적용하지 않으며, 재회 비용은 아래 보정으로 완화되지 않게 한다.

각자의 실제 참여 기록을 최근부터 `r=0,1,...`로 센다. 결석한 모임은 이 순서에 들어가지 않는다. 해당 회차에서 j와 같은 조였으면 `I_ij,r=1`, 아니면 0이다.

- 최근 반복량: `H_ij = Σ_r rho^r I_ij,r`, `0 < rho < 1`
- 상대별 재회 비용: `a H_ij^p`, `a > 0`, `p > 1`
- 개인 재회 비용: 직접 요청 상대를 제외한 현재 조원들의 상대별 비용 합

오래된 만남의 영향은 지수적으로 사라지고 반복량이 커질수록 비용은 가파르게 증가한다. A와 B의 실제 참여 이력이 다르면 서로의 재회 비용도 다를 수 있다. 기록은 편성 전에 발생한 과거 모임만 사용해야 하며, 프로토타입 입력은 이미 과거·최신순으로 준비됐다고 전제한다.

### 보호 이후 완화 (2026-10-09 변경)

보호 기준 순효용은 완화 전 값이다.

`u_i = U_s + U_o - C_year,i - C_reunion,i`

참고용 완화 후 순효용 `v_i = w_i (U_s + U_o - C_year,i) - C_reunion,i`도 별도로 표시한다. 보호 판단은 v가 아닌 u를 사용한다.

전체 편성에서 평가하는 인원의 완화 비중을 반영한 평균 `mu = (sum w_i u_i)/(sum w_i)`와 고정 척도 `s > 0`로 환산한다. 완화 비중이 모두 같으면 일반 평균과 같다.

`z_i = (u_i - mu) / s`

평균보다 불리한 사람의 개선을 더 중요하게 보되, 모두의 순효용이 같은 양만큼 이동하면 중요도는 그대로다. 표준편차·최솟값·최댓값·순위로 정규화하지 않으며, 분포를 정규분포로 변환하는 기능도 아니다. 척도 s는 모임마다 다시 추정하지 않는다.

보호 후 개인 기여분과 실제 비교 점수는 다음과 같다.

`f_i = 1.5 u_i - 0.5 s log(cosh(z_i/2))`

`q_i = w_i f_i - (1-w_i) C_reunion,i`

`W = sum q_i`

재회 비용은 보호 기준 u에 포함한다. 이후 기여분을 w로 줄일 때 빠진 재회 비용 `(1-w_i) C_reunion,i`를 별도로 차감한다. 따라서 재회 비용이 완화되는 일이 없다.

`a_i = tanh(z_i/2)`, `a_bar = (sum w_i a_i)/(sum w_i)`로 두면 성별·학번 순효용의 작은 개선에 대한 중요도는 다음과 같다. 요청 관계와 완화 비중은 고정한 미분이다.

`g_i = 1.5 - 0.25 (a_i - a_bar)`

`실제 개선 중요도 = w_i g_i`

- 보호 계수 g는 1~2 범위다. 완화 이후 실제 개선 중요도는 w~2w 범위이며 서로 다른 w를 가진 사람 사이에서 2배 제한을 의미하지 않는다.
- 낮은 보호 기준 순효용일수록 g가 크다. 같은 u는 같은 g를 받으며 전원의 u가 같으면 g=1.5다. g의 완화 비중을 반영한 평균은 1.5다.
- 전원의 u를 같은 c만큼 개선하면 환산값과 g는 유지되고 W는 `1.5 c sum w_i`만큼 증가한다. 공통 수준은 보호 계수를 왜곡하지 않는다.
- 재회 비용이 조금 증가할 때 전체 점수에서 차감하는 크기는 `w_i g_i + (1-w_i)`로 1~(1+w_i) 범위다. 요청을 충족한 사람에게도 재회 비용은 최소 원래 크기로 반영한다.
- 모든 w가 1인 경우 기존의 환산 보호식과 동일하다. 같은 완화 비중과 같은 총효용에서는 편차가 작은 분포를 선호한다.
- 전체 평균을 일반 평균으로 둔 채 마지막에 다른 w를 곱하면, 평균의 이동으로 한 사람의 개선이 전체 점수를 낮출 수 있다. 보호 이후 완화를 단조롭게 적용하기 위해 평균과 a_bar도 같은 비중으로 계산한다. 개인의 순효용 자체를 먼저 완화해 보호를 높이는 방식과 구별한다.
- `baseUtility`는 보호 기준 u, `utility`는 참고값 v, `protectionWeight`는 g, `effectiveWeight`는 성별·학번의 실제 개선 중요도, `protectedUtility`는 최종 q다. q를 합하면 W이며 u와 g의 곱이 아니다.

고정 척도 `protectionS`와 계수 1.5/0.5 및 다른 파라미터는 유지한다. 독립 검토 평가기는 완화 비중을 반영한 평균 중심 softplus의 동치식으로 전체 점수를 계산하여 앱의 log-cosh 구현과 대조한다. 이 동치식은 개인별 분해값까지 같다는 뜻은 아니다. 완화 비중이 수치적으로 모두 0이면 기준 표시에는 일반 평균을 사용하고 성별·학번 기여는 0, 재회 비용은 전액 남긴다.

보호는 전체 편성에 의존한다. 교환 후보를 평가할 때 교환되는 두 조의 개인 효용만 다시 계산할 수는 있지만, 보호 평균과 점수는 그대로인 다른 조의 사람까지 포함해 다시 계산한다. 조별로 보호한 점수를 단순 합산하지 않는다.

요청이 성별·학번 영향을 완화하면서 양수 평가 기여분을 낮출 수 있는 특성은 유지한다. 명시적인 요청 점수는 여전히 별도 상위 평가다. 이 단계의 점수는 실제 만족도를 측정한 통계가 아니다.

함수의 방향·코드 연결·모의 편성 검증을 거쳐 이번 릴리스의 초기 운영값으로 사용한다. 실제 만족도나 체감 속도를 관측해 추정한 값은 아니며, 운영 사례에 따라 조정할 수 있다. 파라미터를 바꿀 때 성별의 첫 효용/포화 조건, 재회의 감소/볼록성 조건도 검사한다.

2026-10-08 조정: 요청 완화의 속도 `k_request`를 0.5에서 0.25로 낮췄다. 동반 상대 1/2/3명일 때 성별·학번에 남는 영향은 약 0.779/0.607/0.472이며, 이전의 0.607/0.368/0.223보다 천천히 줄어든다. 요청 우선순위와 직접 요청 상대의 재회 비용 면제는 동일하다. 0.25는 사용자가 동의한 방향을 반영한 첫 검토값이며 편성 사례로 적절성을 확인해야 한다. 보호의 중요도는 환산 순효용을 사용하며 1~2배로 제한한다. 고정 환산 척도 2는 검토값이다.

사용자는 재회 비용의 '체감률 증가'를 오래된 만남의 영향이 더 빨리 사라지는 방향이라고 명확히 했다. 이에 `rho`를 0.5에서 0.35로 낮췄다. 개인의 가장 최근/한 참여 전/두 참여 전/세 참여 전 만남의 이력 가중치는 1/0.35/0.1225/0.042875다. 달력상 경과나 불참 모임은 감쇠 단계에 포함하지 않는다. 최근 한 번의 만남 비용 0.6과 반복량의 제곱 비용은 유지한다. 0.35는 방향을 구현한 첫 검토값이며 아직 편성 품질 검증으로 확정한 값은 아니다.

## 앱 연결 범위와 다음 단계

- `buildUtilityContext`는 출석 ID와 회원 ID를 구분하고 명부 중복을 검사한다. 출석→회원 변환은 유지하고 위 요청 인식 정책을 공통으로 사용한다. 기타/미상 성별과 누락 학번은 양쪽 계산에서 제외한다. 결석 상태와 미등록 출석자는 자동 대상에 포함하지 않는다. 수동 조 안의 미등록·결석 인원은 자동으로 제거하지 않고 오류로 안내한다.
- 재회 이력은 편성일 이전의 확정 세션을 날짜순으로 정렬한 뒤 개인별 참석 순서로 감쇠한다. 당일/미래 기록을 제외한다. 직접 요청 상대의 재회 비용을 면제한다.
- 정원을 하나로 결정한 뒤 8개 시작 배치, 시작당 최대 2,000회 무작위 개인 교환 시도와 최대 3회 개인 교환 점검을 수행한다. 기존 탐색을 끝낸 뒤 최대 3회 동반 쌍 교환 점검을 추가한다. 충족된 동반 요청 두 사람을 다른 조의 두 사람과 함께 교환하며, 시작당 쌍 교환 평가는 합계 최대 2,000회다. 쌍 교환을 채택한 점검 뒤에는 개인 교환을 한 번 더 점검한다. 요청 양쪽과 교환 상대 모두 이동 가능한 경우만 시험하며 기존 조원은 수동 고정으로 유지한다. 모든 후보에서 요청 → 운영진 → 전체 개인 효용을 다시 비교한다. 기존 탐색 결과를 구한 뒤 개선만 채택하므로 같은 입력에서 이전 탐색보다 나빠지지 않는다. 탐색은 근사이며 요청 최대 충족이나 전역 최적해를 증명하지 않는다. 동일 입력은 재현 가능한 시드로 탐색한다.
- Worker에서 탐색해 화면을 막지 않는다. 입력 변경/화면 종료 시 Worker를 종료하고 오래된 결과를 버린다. 결과 적용 시 정원과 조원만 바꾸고 조 ID·이름·게임·메모는 유지한다.
- 미충족 요청은 관련 두 조에서 현재 배치를 기준으로 표시한다. 두 당사자가 서로 다른 조에 수동 고정된 것이 확인된 경우에만 그 이유를 안내한다. 그 외에는 같은 조가 아니라는 사실만 알리며 정원 때문에 불가능하다고 추정하지 않는다. 과거 자동 실행의 수동 배치 설명은 입력·결과가 변경되면 사용하지 않는다.
- 일일 조 편성의 인라인 알림은 자동/수동 모드와 관계없이 `AttendanceNotice`의 공통 형태를 사용한다. 동반 요청·재회 주의·첫 참석·전체 편성 안내·평가창 주의·CSV 검토 안내의 글자·여백·테두리·아이콘을 통일하고, 주의는 주황색, 입력 오류는 빨간색으로 구분한다. 저장 결과 토스트와 삭제 확인창은 앱의 공통 구조를 유지한다.
- 점수 창은 개인별 동성/이성 효용·학번 비용·재회 비용·보호 기준 순효용·환산 순효용·보호 계수·완화 계수·참고용 완화 후 순효용·실제 개선 중요도·최종 평가 기여분을 보여준다. 요청/운영진/개인 효용을 단일 비용으로 합산하지 않는다. 미완성 배치는 현재 배치된 등록 참석자만 표시한다.
- 시뮬레이션 내보내기는 사용 파라미터, 결정된 정원, 최종 우선순위 지표, 탐색 중 채택 배치의 점수를 제공한다. 개인 이름/요청 원문은 포함하지 않으며 전체 배치의 무작위 분포를 의미하지 않는다.

`REVIEW_PARAMETERS`는 위 초기 운영값을 담는 상수다. 기본 구현 검증은 합성 데이터로 수행하며, 사용자가 제공한 CSV의 오프라인 모의 비교는 별도 비공개 작업 디렉터리에서 실행한다. 회원 이름·원본 CSV·개인별 모의 결과는 저장소에 포함하지 않는다.

### 성별 효용 후보의 전체 편성 검토 (2026-10-09, 미채택)

첫 동성 동료의 효용이 첫 이성 동료보다 조금 크고, 양쪽 추가 효용이 빠르게 체감하는 후보를 비교했다. 기존 지수식의 상한과 속도를 그대로 조정하면 첫 증가량도 함께 달라지므로, 검토 스크립트에서는 첫 증가량과 후속 증가 비율을 독립적으로 지정한다. `npm run review:gender`로 합성 비교를 재현한다. 앱의 성별 파라미터와 함수는 이 검토로 변경하지 않았다.

비교 함수는 기하급수적으로 감소하는 증가량, 정규화한 쌍곡선, 첫 증가량 이후 더 빠르게 감소하는 구간식이다. 모두 첫 동성 증가량 1.2, 첫 이성 증가량 1, 두 번째/첫 증가량 비율은 각각 0.2와 0.45이다. 기하급수식은 지수 포화식의 재매개화이며, 쌍곡선과 구간식은 다른 함수 형태다. 인원 증가의 효용 자체를 벌점으로 바꾸지 않았다.

모든 참석자를 고정된 정원에 배치하고 전체 보호 점수를 계산한다. 동일 학번·요청/재회 없음·운영진 조건 동일이라는 합성 조건에서는 개인 ID 대신 조별 성별 인원 분포의 전수 비교가 가능하다. 13개 정원 구성과 소수 성별 인원 2명부터 전체의 절반까지의 84개 사례를 비교했다. 최적 동점 중 고립 인원 최솟값/최댓값도 확인하여 열거 순서로 결과가 달라지는 것을 피한다.

| 평가식 | 모든 최적 배치에 소수 성별 고립이 있는 사례/84 |
| --- | --- |
| 기존 값 | 29 |
| 기하급수 증가량 후보 | 42 |
| 쌍곡선 후보 | 42 |

### 성별 파라미터 채택과 보호·완화 영향 (2026-10-09)

사용자는 첫 동성/이성 효용에서 비율보다 점수 차이가 중요하다고 확인했고, 환산·보호·완화 과정에서 비율의 영향이 커지는지 검토를 요청했다. 위 첫 효용 0.9/0.25 및 후속 증가량 비율 0.25/0.65를 앱과 독립 평가기의 기본값에 반영한다. 요청/운영진 우선순위, 학번·재회·보호 척도·요청 완화의 다른 파라미터는 유지한다. 체감은 기존 후속 비율 약 0.301194/0.704688보다 두 항목 모두 빠르다.
